微软商店 Partner Center 用 CSV 批量导入多语言商店一览（附模板和脚本）

Posted on 2026-10-23 In 实用技能

最近给自己的 Xbox 手柄测试工具发新版本，商店一览要支持 8 种语言，每种语言都有说明、新增功能、产品功能、搜索关键字，外加 6 张桌面截图和 6 张 Xbox 截图。在网页上一个个填，光截图就要上传将近 100 次。Partner Center 其实支持用 CSV 批量导入导出，但有个文档里没写清楚的坑：图片路径必须从你上传的文件夹名开始写，否则会直接提示“我们无法处理此 .csv 文件”，而且错误详情是空的。

这篇记录一下完整流程、踩到的坑，并附上内容模板和一个生成导入文件夹的脚本。

TL;DR

  1. 在 Partner Center 应用概述页的「Store 一览」下点「导出列表」，拿到 CSV。
  2. 改 CSV：文字直接改；要换图片就把单元格改成图片的相对路径，并且路径要以上传的文件夹名开头，比如 ListingImport/EN-1.png。
  3. 把 CSV 和图片放进同一个文件夹（就叫 ListingImport），点「导入列表」，选择这个文件夹。

只改文字时，直接导入单个 CSV 就行；要上传新图片才需要导入文件夹。

导出的 CSV 长什么样

入口在应用概述页，当前提交的「Store 一览」下面有三个链接：「添加/删除语言」「导出列表」「导入列表」。导出的文件名类似 listingData-<产品ID>-<提交ID>.csv。

打开后是一张「字段 × 语言」的表：

Field ID Type (类型) default en-us zh-hans …
Description 2 文本 英文说明 中文说明
ReleaseNotes 3 文本
DesktopScreenshot1 100 相对路径(或指向合作伙伴中心文件的 URL) https://…/listingassets/… https://…
…
  • 每一行是一个字段，每一列是一种语言（列名就是语言代码）。
  • Type 列只有三种：文本、相对路径或 URL（图片、视频等资源）、True/False。这一列的文字会随网页语言变化，英文界面导出就是 Text。
  • 已经上传过的图片会导出成 Partner Center 里的网址。导入时保留这个网址，就表示继续用原来那张图。

常用字段和网页上的长度上限（超过会导入失败）：

字段 说明 上限
Description 说明 10000 字符
ReleaseNotes 此版本的新增功能 1500 字符
Title 产品名称，必须是已保留的名称，不能随便改 —
ShortTitle 短标题，空间有限的地方显示 50 字符
ShortDescription 短说明，Xbox 商店等位置显示 1000 字符
Feature1~Feature20 产品功能，商店页以列表显示 每条 200 字符
SearchTerm1~SearchTerm7 搜索关键字 最多 7 个，合计不超过 21 个词
DevStudio 开发者 255 字符
CopyrightTrademarkInformation 版权和商标信息 200 字符
DesktopScreenshot1~30 桌面截图 图片
DesktopScreenshotCaption1~30 桌面截图标题 文本
XboxScreenshot1~30 Xbox 截图，必须是 1920×1080 或 3840×2160 图片

修改 CSV 的注意事项

  • 不要用 Excel 直接编辑保存。 导出文件是 UTF-8（带 BOM）、CRLF 换行，说明这类多行文本是带引号的多行单元格，Excel 另存很容易把编码或多行内容弄坏。建议用脚本改，或者用 VS Code 这类能保留编码的编辑器。
  • 不要动 Field、ID、Type 三列，不要增删行列、不要调整顺序。 只改语言列里的值。
  • 保留原文件名。 文件名里带着提交 ID，我一开始给它改了个短名字，后来虽然证明不是这次失败的原因，但没必要冒这个险。
  • 单元格留空表示清空该字段；图片单元格留空就是删除这张图。
  • 要加新语言，先在网页上「添加/删除语言」，再导出，CSV 里才会有那一列。

最大的坑：图片路径要带上文件夹名

导入时会提示“你可以上传单个 .csv 文件，也可以上传包含你的 .csv、图像和其他资源的文件夹”。要上传新图片，就得选文件夹。我的文件夹是这样的：

按常识，CSV 和图片在同一个目录，单元格里写 EN-1.png 就应该能找到。结果导入直接失败：

我们无法处理此 .csv 文件。请重新导出列表，进行任意需要的更新，然后重试。

点「查看错误」，页面上只有一句“由于文件中有错误，无法导入以下语言的列表”，下面一个语言都没列。这说明整个文件在解析阶段就被拒绝了，而不是某个语言的内容有问题。提示还说“请重新导出”，很容易让人以为是导出文件过期了。

排查过程是一步步缩小范围：

测试 结果 说明
只改文字，所有图片格保持导出时的网址，导入单个 CSV ✅ 成功 CSV 格式和文字内容都没问题，问题在图片
只改一张图，路径写 EN-1.png，导入文件夹 ❌ 失败 和完整导入一样的错误
只改一张图，路径写 ImportTest-Img-B/EN-1.png，导入文件夹 ✅ 成功 路径要带文件夹名

原因大概是浏览器上传文件夹时，每个文件的路径（webkitRelativePath）都是从所选文件夹的名字开始的，比如 ImportTest-Img-B/EN-1.png。Partner Center 直接拿单元格里的值去和这个路径比对，而不是按 CSV 所在位置计算相对路径。只写 EN-1.png 就匹配不上，然后整个文件报错。

所以规则是：单元格里的路径 = 所选文件夹名 + / + 文件在文件夹里的路径。也因此，生成好之后文件夹不能改名，改了名路径就全对不上了。

另外，不同语言的截图文件名经常一样（都叫 1.png），放进同一个文件夹前要改成不重名的名字，比如 EN-1.png、ZH-1.png，免得中文商店里出现英文截图。

模板和脚本

为了以后每次发版不再手动折腾，我写了一个脚本：输入导出的 CSV 和一份内容 JSON，输出一个可以直接导入的文件夹。它会自动处理上面这些坑：

  • 把图片复制进输出文件夹，自动改成不重名的文件名，路径自动加上文件夹名前缀；
  • 保持导出文件的编码、换行和文件名不变；
  • 检查各字段的长度上限、搜索关键字数量、Xbox 截图尺寸，有错误就不生成 CSV。

下载：partner-center-listing-kit.zip，里面是脚本 apply_listing.py 和内容模板 listing-template.json。脚本只依赖 Python 3 标准库，装了 Pillow 会额外检查图片尺寸；也可以单独查看 apply_listing.py。

内容模板

键是语言代码，和 CSV 的列名一致；值是要写入的字段。没写的字段保持导出时的原值：

几条规则：

  • 值是字符串：直接写入同名字段。
  • 值是列表：展开成带编号的字段。"Feature": [...] 会写入 Feature1、Feature2……，列表之后的编号会被清空。截图、截图标题、搜索关键字都是这样写。
  • 图片：写本地路径（相对 JSON 文件），或者写 http 开头的网址保留已上传的图片。
  • 以下划线开头的键会被忽略，可以当注释用。

我这次用它重新生成了 8 种语言的导入文件（说明、新增功能、9 条产品功能、7 个关键字，每种语言 6 张桌面截图和 6 张 Xbox 截图），和手工整理、已经导入成功的那份 CSV 比对：文字字段逐格一致，96 个图片单元格都带着正确的文件夹前缀，并且都指向文件夹里存在的图片。

顺带几个商店一览的小经验

  • Xbox 截图可以在电脑上截。 4K 显示器把 Windows 缩放临时调到 200%，有效分辨率正好是 1920×1080，和 Xbox 上的布局一样；UWP 应用按 Win + Shift + Enter 切到全屏，再全屏截图，得到的就是 3840×2160。截完记得把缩放改回来。
  • 标题不要随便加第三方商标。 产品名称是保留名称，不能在 CSV 里改；名字里带 Xbox 这类商标也容易被认证卡住。可以在版权和商标信息里写一句“Xbox 是 Microsoft 集团的商标，本应用与 Microsoft 无关联”。
  • 搜索关键字写具体需求，别写泛词。 比如“游戏手柄”比“游戏”更容易被搜索到；“Xbox 手柄测试工具”比“Xbox 手柄”更容易被搜索到。
